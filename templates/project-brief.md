# 项目说明模板

按实际需要取用字段，文件名与存放位置由项目决定。可将小项目的需求和设计保存在一份文档中；已经有对应文档时更新原文档。删除不适用的段落，将新文档链接登记到根 AGENTS。

填写要求见 [文档规范](../docs/documentation-standard.md)，完整示例见 [开发准备示例](../examples/preparation-reference.md)。以下是编辑提示，不要把提示原文作为已完成的项目说明。

## 目标与完成条件

- 谁在什么情况下使用，当前要解决的问题。
- 本次需要完成的动作、输入与输出。
- 可以实际观察的验收条件；暂不包含的内容仅记录容易误解的边界。

对每项主要需求连接“动作与输入 → 成功或失败结果 → 验证方法”。可以使用下表，也可以在现有文档中表达：

| 需求 / 验收 | 用户或 Agent 动作 | 期望结果 | 验证方式与状态 |
| --- | --- | --- | --- |
| 按当前任务填写 | 写明输入和触发条件 | 写明结果及必要的失败行为 | 计划 / 已实现未验证 / 已验证 / 未覆盖 |

## 环境与兼容

| 项目 | 决定或实测值 | 状态与依据 |
| --- | --- | --- |
| 目标 DSH 版本及获取方式 | 按本次任务选择 | 计划 / 已核对 / 已验证 |
| Node、包管理器、依赖 | 按实际需要选择并锁定 | 记录真实版本 |
| 目标操作系统 | 由使用需求决定 | 区分开发机与目标验证 |
| API 与文档来源 | 固定版本的链接或类型路径 | 区分资料与实测 |
| 可用工具与运行入口 | 实际查询、安装、浏览器工具 | 列出缺失能力及替代路径 |

## 能力与结构

选择需要的配置、Host、Client、工具、存储或其他能力，并说明原因。已有宿主能力如何复用；必需依赖、可选依赖和数据所有者分别是什么。

写出最少必要文件或模块及职责，区分现有与拟新增；简单项目无需建立目录树或多层架构。涉及多个入口时说明共享的业务操作，涉及持久化时说明重启、迁移与卸载行为。

每个新增模块说明对应需求及职责；公共操作说明关键参数、返回区别、副作用和错误恢复。类型或完整 API 清单已有所有者时链接它，不在文档复制一套。

## 决策与未决事项

只记录影响后续开发的选择及原因，标明来源为用户要求、上游接口要求或项目选择。假设和已确认结论分开，信息充分后开始实现，无需等待所有可选细节确定。

## 验证与使用

列出验收动作、真实命令、环境与观察结果。命令在建立前标为计划，在运行成功后登记为可用；安装方式与实际交付形式一致。保存未覆盖的验证范围。

将验证结果关联上面的验收条目，记录日期、代码版本及未提交修改、环境、操作和实际观察。代码完成后同步需求状态、实际结构和命令，未验证项继续保留。
