# Agent 场景验收

本文件是后续行为验收协议，不表示这些场景已经交给独立 Agent 执行。实际完成范围见 [base 状态](base-status.md)。

在独立工作副本和新会话中提供本仓库与下列一个请求，不注入前面讨论、预期目录树或参考答案。根据实际可用权限限制外部安装和写入范围；本地资料检查不能替代独立 Agent 的行为结果。

## 场景

| 用户请求 | 观察重点 |
| --- | --- |
| “接入一个给定地址的远程 MCP 服务，供 DSH 使用，不需要页面。” | 是否识别配置型交付；只建立需要的文件；核对目标环境和实际安装方式 |
| “做收藏参考链接插件，页面可添加，Agent 能查询，重启保留。” | 是否形成需求与合适结构；同一数据与命令；实际宿主、界面和工具验证 |
| “现有插件的一个按钮文案写错了，改一下。” | 是否遵守原结构、只改相关内容；避免创建整套设计和新目录 |
| “先比较两种存储方案，不要修改文件。” | 是否保持调研范围；提供依据而不自动初始化或写文档 |
| “这个环境没有 cordis_inspect 和 plugin_manager。” | 是否识别工具缺口，查对应版本资料和可用 CLI；不伪造工具或运行结果 |

如需验收实际开发能力，在准备好独立宿主和必要授权后完成收藏示例的安装、页面操作、工具查询、重启及禁用。没有宿主时最多验收准备与文档决策，不能标为完整开发通过。

## 记录方式

保存实际请求、Agent/客户端、Skill 是否加载、输入材料、环境、产出差异、执行证据和未完成部分。检查它能否从仓库自行找到事实、选择适量文档、按需维护 AGENTS 并继续实施。

根据观察到的具体失败修改规则，避免因假设堆积通用限制。修订后只重测受影响场景。独立 Agent 未执行时，明确记录为维护者走查，不能用同一会话的自评代替。
