# DSH 插件开发

先读仓库 [AGENTS.md](../../../AGENTS.md)。这是本仓库编写的开发 Skill，并非官方 Skill 副本。官方依据、适配和本地选择见 [来源映射](../../../docs/source-map.md)；加载它不会安装宿主、获得宿主工具或创建业务插件。

## 根据任务规模准备

- **新项目或新增独立插件**：按 [开发准备](references/preparation.md) 识别需求、能力、版本和环境，再选择结构。第一条实现路径应能在目标宿主验证。
- **现有插件新增功能或调整边界**：复用已有约定，只更新受影响的需求、设计、规则和验证方法。
- **小修复、文案或局部布局**：读取相关约束、定位真实问题并明确验证方式即可，不创建完整设计文档或额外目录。
- **评审或调研**：先读取现状与相应参考，输出发现和依据；用户未要求实施时，不自动初始化工程或改写文档。

## 准备完成的条件

新项目或非简单功能在现有文档或新记录中留下五项依据：目标与可观察验收、环境和接口来源、设计与文件影响、实施和验证路径、关键假设与未决项。按文档规范检查内容完整性；单个文件可以同时承担这些职责，不以文件数量验收。

能够说明用户目标与可观察验收、相关宿主接口及证据、计划修改的文件及职责、实际验证入口，即可开始开发。新宿主基线尚未验证时，先把“最小构建产物能安装、加载、调用或显示、卸载”作为第一项实现任务。

能力和目录由需求决定：配置型连接器可以没有业务源码；纯工具插件可以没有界面；需要界面才引入 Client；需要持久化才选择存储。不要先建立一套完整分层再寻找用途。

官方 Creator 环境的查询和安装工具仅在本次会话实际提供时使用。否则查锁定版本的声明与文档，使用已核对的 CLI 或加载入口。上游仓库内的构建命令、相邻工作区依赖和内部包命名不能直接复制成外部项目契约。

## 实施与收尾

先完成最小完整路径，随后迭代本次要求。多个入口操作同一业务时复用业务命令；注册和资源释放归属明确；界面通过宿主扩展点接入。

实现中改变结构或选择时同步相关设计；AGENTS 只更新长期规则、开发入口和已建立的命令。不要用进度记录覆盖用户约束，也不要提前将计划改成“已完成”。

将验收动作与真实结果对应，检查实际发布视图和宿主行为。按文档规范同步接口说明、命令、文件链接和状态；没有证据的行为继续标为未验证。多轮任务将未决事项和下一步留在本次任务记录中；小任务在现有记录中收尾即可。
