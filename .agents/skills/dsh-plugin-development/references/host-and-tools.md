# Host、工具和数据

仅在需要 Host 行为、工具、外部能力或持久化时读取。接口名称和方法签名查 [上游索引](../../../../docs/upstream.md) 的基础开发、工具及生命周期资料。

## 先决定归属

同一业务由一个明确实现负责。页面、Agent 工具和可选 MCP 适配器调用它，不分别维护校验或数据状态。简单插件可以在少量文件中完成；仅为独立变化、替换或复用的能力引入独立服务。

区分必需与可选依赖：缺失必需能力时给出准确状态；可选能力缺失时保留独立功能。跨插件通过明确服务或数据契约协作，避免导入对方内部组件或直接修改对方存储。

## 工具的完成条件

为工具定义明确用途、参数约束和规范返回值，核对目标版本支持的注册与输出机制。工具名称、描述和错误应足够让模型选择并理解结果；只注册成功不等于模型会正确使用。

索引固定版本的官方教程使用 `defineTool`：`parameters` 描述并校验输入，`execute` 返回 `output.schema` 所定义的规范结果，`output.render` 将结果转换为模型内容。应核对实际版本的这些声明，避免把模型展示文本当成业务返回结构。注册所需的 `tools` 服务依赖与清理方式由实际接口确定，示例命令不等于本仓库已有命令。

按照 [文档规范](../../../../docs/documentation-standard.md) 写清工具的输入前提、结果区别、副作用和错误恢复；自动生成的参数清单链接回源码或生成结果，不再手工维护完整副本。

让界面与工具执行同一业务动作，验证双方能够读到一致结果。工具测试直接调用通过、工具暴露给 Agent、真实模型正确调用是不同证据，分别记录。

## 存储与生命周期

需要持久化时明确存储所有者、位置、迁移策略和故障反馈，选择满足需求的格式；不预设数据库、共享后端或额外 HTTP 服务。配置与凭据通过实际环境支持的机制传入，避免进入浏览器产物与日志。

订阅、工具注册、定时器和进程归属插件生命周期，处理禁用与重载后的释放。数据保存成功后再通知使用方。卸载的数据保留或清理行为属于产品约定，开发前说明并据此验证。

确有需要时引入辅助进程，交代启动、退出、取消和恢复的所有者；据目标系统验证行为。不要把官方仓库自己的测试运行器或构建预设当作独立包依赖。
