# 打包、运行与验证

编码前或涉及构建、安装、升级、排错时读取。[上游索引](../../../../docs/upstream.md) 提供对应文档；不要把此文件的检查项目当作现成可执行命令。

## 先记录兼容基线

记录准确 DSH 版本或源码提交、安装方式、Node 和包管理器版本、依赖锁定方式、目标系统、Agent 可用工具及实际开发命令。源文档研究提交与已跑通的宿主版本分别记录。

官方 Creator 的 `plugin_manager` 和 `cordis_inspect_*` 仅在实际提供时使用。外部开发环境使用目标版本可用的 CLI、类型声明和加载入口。缺少能力时明确缺口；不要调用不存在的工具，也不要为获取开发环境擅自改用户的常用 profile。

为插件开发建立独立测试 profile 或等效隔离环境，确认它包含本次需要的 Web 或其他宿主能力。按需建立可重复运行的本地脚本，并在成功运行后登记命令。

## 检查分发视图

根据交付方式核对包 manifest、配置 patch、入口导出和必要资源。bundle 是分发内容，profile 是运行组合；独立插件无需复制整套宿主工程或用户 profile。

有 Client 时核对其实际构建格式和共享运行时。发布清单包含运行所需代码与资源，不把开发 Skill、测试数据、日志或凭据误作运行依赖。

源码运行、链接安装和 tarball 安装是不同路径。针对打算交付的形式验证，至少有一次从构建产物完成真实加载，避免只在相邻源码 checkout 存在时才能运行。

索引固定版本中需要区分的声明：

| 声明 | 含义与检查 |
| --- | --- |
| `dsh.bundle.patch` | 指向贡献 profile 配置层的文件；普通依赖安装不等于启用了 bundle |
| Host 入口与 patch 行 | 按实际发布包解析，而非依赖开发机相邻仓库路径；patch 覆盖目标配置时核对完整值 |
| `./client` 与 `dsh.client` | 有浏览器能力时核对其导出、平台、构建产物和所需资源 |
| 服务 `inject`、`dsh.client.inject`、`external` | 分别涉及服务注入、包信息与模块解析，不可互相替代；按目标版本核对 |
| 发布 `files` | 覆盖所有运行时相对引用及资源，排除无关开发资料和本地数据 |

参考 [插件使用说明模板](../../../../templates/plugin-readme.md) 编写与真实包类型相符的 README；安装命令、默认配置和重启行为必须有对应实测或明确的未验证状态。

## 按修改范围选择验证

| 改动 | 需要的证据 |
| --- | --- |
| 文档与开发 Skill | 链接、入口、适用范围；必要时做独立场景试用 |
| 业务规则或接口 | 参数、结果、失败路径，以及共享入口的一致性 |
| 包结构、导出或构建 | 实际交付包安装与真实 Loader 加载 |
| 页面与交互 | 真实宿主用户操作、相关主题及状态表现 |
| 数据与升级 | 重启、必要迁移、失败恢复符合声明 |
| 注册与后台资源 | 禁用、重载、退出释放资源，重新启用不重复注册 |
| 目标平台能力 | 在目标系统验证相应路径；其他系统结果分开记录 |

检查失败时从具体错误出发定位，保留有效证据；通过后仅在后续修改或新问题影响结论时重跑。简单文案或布局修改无需为实现细节建立镜像测试。

记录真实执行的命令、环境、结果及未验证项。静态检查、构建成功、宿主加载、用户操作、模型实际调用各自证明不同层次，不能互相代替。
