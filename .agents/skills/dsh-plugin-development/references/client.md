# 原生 Client 开发

仅在涉及界面时读取。[上游索引](../../../../docs/upstream.md) 中的 Client 规范、Slots、公共组件和样式资料是接口核对入口。[来源映射](../../../../docs/source-map.md) 标明官方原文及本地适配，具体 API 以目标版本为准。

## 选择扩展点

确认目标页面、入口和交互结果，再检查对应 Slot 的协议、注册参数、props、当前占用及声明时机。优先选择足够承载需求的局部扩展点。插入业务页面不需要重新实现宿主根布局。

会话中有查询工具时使用实际返回的 Provider 和方法；没有时检查目标版本类型与文档。不要猜 Slot 名称、props 或通过产品 DOM 选择器挂载第二套应用。

## 组织代码

让 `ctx` 留在注册和注入层，业务组件接收框架推导的数据与回调。复用现有宿主数据通道，避免重复订阅、复制业务状态或为了页面已有的数据再新增 RPC。

先查公共组件是否满足需求；原生页面使用宿主的语义主题、语言和样式机制。独立选择新组件库或应用壳前，先确认需求与宿主兼容方式。沿用另一项目的 UI 模板不能证明符合 DSH 规范。

共享 React 等运行时的方式、Client 导出、浏览器模块表和资源打包按目标版本核对。不要复制上游相对构建路径、发布命名空间或包内维护专用规则。

## 已核对的具体规范

以下来自索引固定版本的 Client 和 Web 样式规范，采用其他宿主版本时核对相应声明。

| 位置 | 实现约束 | 开发时核对什么 |
| --- | --- | --- |
| Slot 注册 | 在插件生命周期内注册；等待目标 Slot 声明，不用包加载顺序推断已可注册 | Slot 的类型、props、注册参数和 `slots.inject` 等实际 API |
| 组件输入 | `ctx` 留在注册/注入层；组件消费推导 props、框架提供的数据与回调 | 是否自行重写框架 props，或直接把服务实例传进业务组件 |
| 状态 | 宿主业务数据使用其所属数据通道；共享视图状态、组件局部状态各有所有者 | 是否重复订阅或将同一业务事实复制进另一份 store |
| 控件与样式 | 复用 `ui-primitives`，使用 CSS Modules 与 `clsx`，消费 `--dsw-alias-*` 语义变量 | 不添加 Tailwind 或另一套组件库；不复制色板、不在业务 CSS 写主题分支 |
| 文案与交互 | 产品文案通过 typed locale 与 `t` 或本地化 props 提供；保留焦点与减少动画设置 | 标题、占位文案、提示、状态和可访问性名称是否一起处理 |
| 跨插件协作 | 行为通过服务，界面通过 Slots，类型可 type-only 引用 | 不直接依赖另一业务插件的实现组件或私有导出 |

这些是该版本原生 Client 的开发依据。若用户需要另一种嵌入方式，应先说明与原生规范的区别并明确兼容目标，而非默认把标准放宽。

## 可观察验收

在真实宿主中检查入口、主流程、加载/错误/空状态、键盘操作及本次涉及的窄窗口表现。对选定主题实际验证文字、控件、弹窗；声明哪些主题通过，而非承诺任意皮肤都兼容。

浏览器不可用时记录可完成的构建和加载检查，将视觉行为列为未验证。独立页面截图、设计稿或 Slot 注册结果不能替代实际渲染证据。
